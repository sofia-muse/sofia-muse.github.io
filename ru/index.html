Устаревшие записи и конфликтующие запросы возвращают понятные ошибки.

Технические решения

Безопасные повторы

Эндпоинты выпуска и отмены принимают ключ идемпотентности. Тот же ключ и данные возвращают исходный результат; изменённые данные вызывают конфликт.

Правила на двух уровнях

У клиента может быть не более одного активного автомобильного полиса. Это правило защищают проверки сервисов и фильтрованный уникальный индекс SQL.

Параллельные изменения

Токен версии строки выявляет устаревшие обновления полиса: возвращается конфликт вместо незаметной перезаписи чужого изменения.

Прослеживаемый жизненный цикл

Выпуск, обновление и отмена полисов создают события аудита. При отмене запись сохраняется, а отменённый полис нельзя изменить.

Запись с защитой JWT · лимиты запросов · тесты xUnitЛичный проект

Тесты и контракты

Тесты эндпоинтов на xUnit проверяют конфликтующие ключи идемпотентности, повторные запросы, валидацию, права JWT и ограничения частоты запросов.

СТРАХОВОЙ API / НАДЁЖНОСТЬ

Предсказуемые повторные запросы

Почему повторный запрос должен возвращать стабильный результат.

Клиент может не получить ответ, даже если сервер уже сохранил данные. Повторный запрос не должен создавать ещё один полис.

В моём страховом API операции выпуска и отмены принимают ключ идемпотентности. Совпадающие ключ и данные возвращают исходный результат; изменённые данные вызывают конфликт.

Реализация сохраняет операцию, ключ, отпечаток данных и ID сущности ответа. Уникальное ограничение на операцию и ключ предотвращает неоднозначное повторное использование.
