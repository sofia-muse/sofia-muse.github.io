Insurance Management API

Бізнес-правила й передбачуваний запис даних у власному API на .NET.

Завдання

Керувати клієнтами й життєвим циклом полісів, обробляючи повторні запити та конфліктні зміни.

Моя роль

У цьому власному проєкті я реалізувала backend, бізнес-правила й тести API.

Рішення

API на .NET 8 для керування клієнтами та життєвим циклом полісів автострахування, медичного страхування й страхування життя. В основі — бізнес-правила, передбачувані помилки та надійний запис даних.

Технічні рішення

Безпечні повторні запити

Операції випуску та скасування приймають ключ ідемпотентності. Однакові ключ і дані повертають початковий результат; змінені дані спричиняють конфлікт.

Правила на двох рівнях

Клієнт може мати лише один активний поліс автострахування. Це правило забезпечують перевірки сервісу та фільтрований унікальний індекс SQL.

Одночасні зміни

Токен версії рядка виявляє застарілі оновлення поліса й повертає конфлікт замість непомітного перезапису чужих змін.

Відстежуваний життєвий цикл

Випуск, оновлення та скасування полісів створюють події аудиту. Скасування зберігає запис, а скасовані поліси не можна змінювати.

Захист запису через JWT · обмеження частоти запитів · тести xUnitВласний проєкт

Тести та контракти

Тести кінцевих точок xUnit перевіряють конфліктні ключі ідемпотентності, повторне повернення результату, валідацію, дозволи JWT та обмеження частоти запитів.

var existingIdempotency = await GetIdempotencyAsync(operation, idempotencyKey, cancellationToken);
